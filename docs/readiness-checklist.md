# YC readiness checklist

Planning baseline: 26 October 2026. Checkboxes are work tracking. Close an evidence gate only after attaching an inspectable dated artifact to the [ledger](evidence-ledger.md). The browser checklist is device-local and does not change these records.

## Immediate decisions

- [ ] Confirm the sensor model, outputs, calibration and available rig/instrumentation.
- [ ] Confirm founder names, roles, full-time dates, history working together, ownership and decision process.
- [ ] Select target batch and verify the current live application fields/deadline.
- [ ] Choose one first buyer and one workflow to investigate; write the current alternative.
- [ ] Decide which first PoC gate can be honestly completed before submission.

## Technical evidence

- [ ] G0-G2: rig feasibility, calibrated acquisition and provenance.
- [ ] G3-G4: separate contact/observation model and frozen calibration/evaluation split.
- [ ] G5: matched baseline, physical accuracy, speed/memory and failure report.
- [ ] G6: runnable example and recorded demo from the actual code.
- [ ] G7, if ready: frozen synthetic-trained perception evaluated on real data.
- [ ] G8/G9 only if achieved: qualify feedback versus policy transfer and disclose calibration/adaptation.

See the [build plan](poc-build-plan.md). An unfinished gate is a status to report, not a reason to invent a completed result or an automatic bar to applying.

## Customer and business evidence

- [ ] Interview actual sensor users and budget owners about recent work, alternatives and measurable costs.
- [ ] Record dated observations, contradictions and follow-up permission; do not count friendly interest as a pilot.
- [ ] Obtain a concrete test workflow, sample input/output and success criterion from a prospective user.
- [ ] Verify ownership/terms before using customer data or redistributing dependencies.
- [ ] Test packaging and pricing with an identified buyer; label assumptions until accepted.
- [ ] Build a bottom-up market worksheet from counted customers and evidenced spend, with uncertain inputs explicit.

## Written application and videos

- [ ] One clear company description, with planned capability distinguished from current implementation.
- [ ] Dated progress delta with artifacts; synthetic/development qualifiers retained.
- [ ] Competitive answer that acknowledges existing tactile features and strongest prior work.
- [ ] Founder facts, equity, commitments, location, fundraising, burn and runway verified by the founders.
- [ ] Record the founder introduction following the live YC instructions, separately from the product demo.
- [ ] Record an honest working demonstration; visible measurements correspond to saved logs.
- [ ] Test final links in a signed-out/private browsing session under the required permissions.
- [ ] Human founders review the final form, factual claims, attachments and permissions before submission.

## Interview preparation

- [ ] Everyone understands the product, current status, alternatives and largest unresolved risk.
- [ ] Have a live demo ready and a backup recording.
- [ ] Practice answering actual questions concisely without memorizing speeches; allow follow-ups.
- [ ] Each founder can contribute in their area. Agree who starts each topic; avoid a rigid CEO speaking quota.
- [ ] Keep a short accurate facts sheet available. Use notes for numbers when useful.
- [ ] Discuss the NVIDIA/platform threat, calibration/generalization risk and customer willingness to pay candidly.

The [guidance audit](yc-guidance-audit.md) separates official instructions from heuristics in the supplied advice. Application preparation does not authorize submission, outreach or publishing.
